# CineRAG

Ask questions about movies and get answers grounded in relevant passages from the movie dataset.

Live Link:https://cine-rag.vercel.app/

## Features
- Natural-language movie Q&A
- Semantic vector retrieval over movie-data chunks
- Neo4j graph retrieval across movies, actors, directors, genres, and reviews
- Local answers generated by the Ollama `qwen3.5:4b` model and grounded in the bundled movie dataset
- Optional OpenRouter chat and embedding support

## Architecture
- The chat UI posts the question to `/api/chat`.
- `/api/health` checks the Neo4j connection and returns `neo4j: "connected"` when the configured database is reachable.
- The backend reads `server/notes.txt` (or `server/notes.pdf` if the text file is absent) and splits it into overlapping chunks.
- When `CHAT_PROVIDER=openrouter` and embeddings are enabled, `openai/text-embedding-3-small` embeds each chunk. The backend caches those vectors in memory for the lifetime of the server process.
- With OpenRouter selected, each question is embedded and compared with the chunk vectors using cosine similarity. The four closest chunks are sent to the configured OpenRouter chat model as context for the answer.
- The backend parses movie and review records and upserts them into Neo4j Aura using Cypher over Neo4j's HTTPS Query API. The graph contains `Movie`, `Person`, and `Genre` nodes connected by `ACTED_IN`, `DIRECTED`, `IN_GENRE`, and `REVIEWED` relationships.
- Graph retrieval matches movie, person, or genre names in the question, then traverses up to two graph hops to find related movies and their cast, genres, ratings, synopsis, and sample reviews.
- Local development uses the Ollama model (`qwen3.5:4b`) by default, regardless of whether an OpenRouter key is configured. This mode does not require embeddings or a Neo4j connection.
- On Vercel, an `OPENROUTER_API_KEY` selects OpenRouter by default because the deployment cannot reach Ollama on your computer.
- Set `CHAT_PROVIDER=openrouter` and configure `OPENROUTER_API_KEY` to use OpenRouter for answer generation, vector embeddings, and optional graph retrieval.
- Vector embeddings are cached in memory per backend process. Graph data is loaded idempotently into Neo4j when OpenRouter graph retrieval first runs.

## Tech stack
React and Vite provide the chat UI; Node.js runs the retrieval backend; Ollama provides default local answer generation, with OpenRouter available as an opt-in provider; Neo4j Aura stores the graph; Cypher queries it through Neo4j's HTTPS Query API using Node's built-in `fetch`; and Vercel hosts the deployed API.

## Getting started
1. Install the frontend/backend shared dependencies with `npm install`.
2. Install the local Express server dependencies with `npm --prefix server install`.
3. Optional: create a Neo4j Aura instance and note its connection URI, username, and password if you want graph-backed answers.
4. For local chat, install and start Ollama, then make sure `qwen3.5:4b` is available (`ollama run qwen3.5:4b`). The local backend uses this model by default. `OLLAMA_MODEL` can override the model name and `OLLAMA_BASE_URL` can override the Ollama address (default `http://127.0.0.1:11434`). To explicitly use OpenRouter locally, set `CHAT_PROVIDER=openrouter` and configure `OPENROUTER_API_KEY`. On Vercel, configure `OPENROUTER_API_KEY` to use OpenRouter by default, or set `CHAT_PROVIDER=ollama` with an Ollama endpoint reachable from Vercel. Optional Neo4j settings are `NEO4J_URI`, `NEO4J_USERNAME`, and `NEO4J_PASSWORD`; `DISABLE_EMBEDDINGS=true` skips vector search when using OpenRouter. `NEO4J_URI` accepts a Neo4j Aura `neo4j+s://` URI or an HTTPS Query API URI; for Bolt URIs, the Bolt port is not used as an HTTPS port. `NEO4J_DATABASE` is optional; for Aura URIs the backend defaults to the instance ID from the hostname, and for other HTTPS Query API hosts it defaults to `neo4j`. The local server loads the root `.env` even when started with `npm --prefix server start`.
5. Start the backend with `npm --prefix server start` and the frontend with `npm run dev` in separate terminals.

The Vite development server proxies `/api` requests to the local backend on port 8000. Check `/api/health` locally or on the deployed app to verify Neo4j connectivity; a failed health check includes a diagnostic error message. The backend accepts `NEO4J_USERNAME` (or `NEO4J_USER`) for the database username. The deployed app uses serverless handlers in `api/`.
